# Storyfolio · 本地简历工作台

保存原始故事，整理完整经历库，为不同 JD 起稿，再编辑、排版、导出。资料保存在本机，可以同步到自己的 GitHub **私有**仓库。公开源码不包含任何个人资料或密钥。

## 启动

需要 Node.js 22 或更新版本。主程序没有 npm 依赖，无需 npm install。

Windows 双击 **启动工作台.cmd**，浏览器打开 http://127.0.0.1:4317 。或者在项目目录运行：

```sh
npm start
```

Word 导出另外需要 Python 3 和 python-docx：

```sh
python -m pip install python-docx
```

服务只监听本机。关闭浏览器后数据仍然保留；重新启动电脑后再运行启动文件。启动脚本将服务放在后台，日志在 data/server.log 和 data/server-error.log。

## 使用顺序

1. **原始故事**：逐条记录完整过程，或导入 MD/TXT。记录与整理分开，故事原文不会被 AI 覆盖。
2. **我的经历库**：可直接导入已有经历库；也可点击“从故事整理”，审阅候选稿后采纳。
3. **模型与同步**：填写姓名、联系方式、作品和到岗信息；设置模型 API；调整风格规则。
4. **简历工作室**：粘贴 JD 生成候选稿；正文、编辑说明和待确认问题分开显示。采纳后建立独立岗位简历。
5. **编辑与排版**：左侧编辑 Markdown，右侧实时预览；选中文字可局部 AI 改写。可调整板块顺序、字号、行距、边距、字体、主题色和两种模板。
6. **导出**：PDF 使用浏览器“另存为 PDF”，建议关闭页眉页脚；Word 为可编辑 DOCX；也支持 Markdown、HTML 和完整 JSON 备份。

文件名采用已填写的“姓名+岗位+公司”。缺少姓名/公司时不会编造，可在设置和岗位字段补齐。

## DeepSeek 配置

默认 API 地址：https://api.deepseek.com

默认模型：deepseek-flash

截至 2026-11-13，DeepSeek 官方文档说明该标识由 DeepSeek-V4.1-Flash-1017 提供服务。可在设置里更改为其他兼容 Chat Completions 的模型。API Key 在本地输入，不提交到源码仓库。云端模型会接收本次生成所需的完整故事、经历库、个人资料、JD 和风格规则。

没有配置密钥时，本地编辑、版本保存、导入导出仍可用；不会展示伪造的 AI 生成结果。

## GitHub 同步与恢复

- 源码仓库可以公开，资料仓库必须私有。先在 GitHub 创建私有仓库。
- 设置里填“用户名/仓库名”和仅授予该仓库 Contents 读写权限的 fine-grained Token。
- 点击保存连接设置，再点击“上传本机版本”。所有资料和版本历史保存为 `resume-workbench/workspace.json`。
- 换电脑后，先启动工作台并配置同一仓库与 Token，再点击“查看云端版本”，可下载备份或恢复到本机。
- 同步是显式上传/恢复，不是多人实时协同。云端 SHA 变化时拒绝覆盖；先下载云端备份，再决定保留哪个版本或手动合并。
- 首次连接已有资料的仓库不会直接覆盖。恢复云端版本和导入备份前会在本机 `data/backup-*.json` 留存当前完整资料。
- 单次 GitHub 备份限制为 950 KB。接近限制时请下载完整备份，后续版本可扩展为按简历和版本拆分文件。

## 数据与记忆

`data/workspace.json`：故事、经历库、个人资料、风格、简历、排版和历史。

`data/settings.local.json`：模型与 GitHub 连接设置，密钥仅保存在该本机文件，当前未加密。

`data/sync.local.json`：云端版本 SHA 与本地同步指纹。

原文以全文进入模型上下文，不先压缩成摘要。修改中的内容自动保存；每轮编辑会自动留档，重要版本也可手动保存。恢复版本会再保存恢复前内容。修改满两分钟后再输入会产生新的自动快照。

完整备份只包含白名单资料字段，不包含连接密钥。不要把 data 目录上传到公开仓库。

## 风格说明

默认规则来自用户对“阿苏在 coding”简历表达的明确要求：教育置顶、有依据的身份定位、项目分量到本人角色、按目标 JD 选择工作模块、保留方法和成果的细节。当前未持有原版简历，因此不是其版式或全文的精确复刻。可在设置里加入自己认可的示例。

## 验证与限制

```sh
npm test
```

集成测试使用临时数据目录和模拟模型/GitHub 服务，覆盖本地持久化、并发冲突、原文进入上下文、候选不自动覆盖、DOCX 导出、同步与恢复、公开仓库保护及密钥隔离。真实模型和 GitHub Token 需要用户在本机配置后验证。

- PDF 由浏览器打印引擎生成；屏幕预览为连续 A4 比例内容，精确分页以打印窗口为准。
- Word 与 HTML/PDF 使用不同排版引擎，分页可能不同。
- 编辑采用 Markdown 与实时预览；不是 Word 式拖动文本框的所见即所得编辑器。
- 当前原文导入支持 MD/TXT；不含 PDF/OCR/语音解析。
- 当前同步为整份快照，不自动合并两台电脑的同时编辑。
- AI 输出应经用户审阅；不会把“关键词分数”当作真实招聘匹配度。
