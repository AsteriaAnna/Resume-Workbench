# 履历工作台 · 0.3.0

保留现有深色图谱和文档工作台风格，统一经历资料与简历生成的数据来源。

## 启动

需要 Node.js 22 或更新版本；运行 `npm start`，打开 http://127.0.0.1:4321 。也可双击原启动脚本。

模型在设置页配置，密钥仅保存在本机。`WORKBENCH_PORT` 可修改端口，`WORKBENCH_DATA_DIR` 可指定资料目录。默认资料目录为 `prototype/local-data/`。

## 工作方式

1. 经历库：创建经历、选择归属后补充；全文、原话、节点关系和对话记录保留。基础信息独立编辑。节点可以归档和恢复。
2. 简历管理：按文件夹、公司、岗位、投递状态管理；每次实际修改保存版本，支持副本、重命名和历史恢复。
3. 简历制作：JD → 完整经历和原话 → 可编辑大纲 → 成稿与来源核验 → 审阅应用。大纲可调整顺序、取舍、关键词和阅读路线。
4. 编辑与打磨：Markdown 正文、预览、两种标题样式、字号、行间距、留白、栏目顺序；AI 评论分表达建议与事实补充，后者先回写所属经历再提出局部修改。
5. 导出：Markdown 下载；PDF 通过打印预览另存。尚不提供 DOCX 导出。
6. 调试：设置中的提示词编辑和运行记录；生成任务保存每步输入、输出、错误和耗时。原 `/debug` 为旧链路调试台，新成稿链路以简历内“运行记录”为准。

## 数据与迁移

Wiki 快照是唯一经历源；不再要求将 Wiki 手动导入 v2 卡片库。少量经历全量读取，Story 用于组织表达，并不强制一故事对应一行。

简历保存在 `studio/resumes`，历史在 `studio/history`，任务在 `studio/jobs`。首次读取简历列表迁移旧 `resumes.json`，并将旧 v2 运行记录中的回答补回对应经历；原文件保留。未能关联经历的历史回答不自动写入。

升级前备份整个资料目录，再设置 WORKBENCH_DATA_DIR 指向副本进行检查。旧程序回退时使用旧资料备份。原始个人资料、模型配置与测试资料均不提交公共仓库。私有仓库同步仍由设置页手动触发。

## 验证

`npm test` 运行重构模块测试；`npm run test:legacy` 验证原始存储、经历类型、归属和索引兼容。详细范围与限制见 [重构验证记录](design/重构验证记录-2026-11-23.md)。
