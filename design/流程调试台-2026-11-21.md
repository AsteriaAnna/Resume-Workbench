# 流程调试台

入口：启动工作台后打开 `http://127.0.0.1:4321/debug`，或点击工作台顶部的「流程调试」。

## 可直接在页面调整

1. **AI 节点提示词与连接**：点击节点查看当前提示词、默认提示词和历史版本；保存新版后，后续正式操作立即使用。可恢复默认。点击连线可查看传递内容、触发条件与实现位置。经历入库、引导提问、JD 策略、查询计划、证据评估、选材、大纲、评论修订、正文、追溯、校验、修复以及简历评论均在同一列表中。
2. **模型连接与流程参数**：填写兼容 DeepSeek Chat Completions 的 HTTPS 地址、模型名称和密钥；留空密钥保持原值。密钥不回显，环境变量 `DEEPSEEK_API_KEY` 优先于本机配置。还可设置正式运行的默认检索分支，以及事实校验阻断后是否自动修复一次。
3. **单节点试跑**：输入该节点的 JSON 输入；输出只显示在调试台并写入本机轨迹，不写入 Wiki 或简历。可从已有轨迹复制实际输入。
4. **整链路运行与对比**：粘贴 JD 新建运行，或选旧运行用同一 JD 复跑。可选 `index`、`fulltext`、`index_fallback`，并决定是否生成正文。原运行和新运行并列展示查询计划、候选经历、证据评估、选材、大纲、正文与校验。
5. **节点输入输出**：正式工作台每次入库、引导提问、大纲、评论修订、成稿和简历评论都会保存逐节点模型输入、输出、耗时及错误。索引命中、选材约束、大纲清理、来源结构检查和快照提交等程序判断也记录在轨迹中。点击运行轨迹可检查。

## 连接与存储

流程图由 `prototype/debug.mjs` 的阶段和连接清单生成，节点名称对应真实任务名。模型提示词位于 `prototype/llm.mjs`，本机覆盖版保存在 `prototype/.local-debug.json`。模型连接保存在 `prototype/.local-ai.json`，流程规则参数保存在 `prototype/.local-workflow.json`；三者都被 Git 忽略。运行结果在 `prototype/local-data/runs/`，调试轨迹在 `prototype/local-data/debug-traces/`；轨迹不进入 GitHub 资料备份。

程序规则节点（归属检查后的快照校验、按 Experience 检索、保存）可以查看输入输出和连接，暂不支持在画布上任意拖线改执行顺序。这些节点的契约依赖稳定 ID、来源引用和快照校验；任意改线会造成无效引用或资料写入错误。检索分支通过运行面板的模式选择调整。Wiki 入库会写资料，调试时建议先用单节点试跑观察模型输出。

调试轨迹包含完整 JD 和经历文本，仅供本机查看。整个 JD 复跑会产生模型请求和新的本地运行记录；单节点试跑不会自动执行下游校验。
