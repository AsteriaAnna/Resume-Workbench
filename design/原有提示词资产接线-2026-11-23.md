# 原有提示词资产接线 · 2026-11-23

基线：main d17e8f9。原始提示词均保留在 `prototype/llm.mjs`；原始规则链保留在 `prototype/workbench.mjs`。本轮将当前工作台的新简历入口重新接到原链，不复制改写这些提示词。

## 经历入库

`app.js → /api/wiki/create 或 /api/wiki/input → updateWiki → check_extension（补充时）→ wiki_update → 校验/快照/对话记录`。`guide_questions` 仍用于所选经历的引导提问。基础信息直接保存。原始输入保留于 raw，Wiki 节点保存于快照。

## JD 到大纲

`studio UI → studio.execute(outline) → workbench.generate → strategy → query_plan → experienceIndexParts 索引 → evaluate（按要求、以完整 Experience 为单位）→ index_fallback 全经历兜底 → selection → selection_guard → outline → outline_guard`。输出原有 run_id、strategy、query_plan、discovery、evaluation、selection 与大纲；界面保存 run_id，用户可以编辑大纲。索引只用于候选定位，评估时读完整经历和原话。

## 大纲到成稿

`studio UI → studio.execute(compose) → workbench.compose(run_id, 用户已编辑的大纲) → compose → trace_claims → claim_guard → verify → 有 block 时 repair → 再追溯与核验`。候选稿仍由用户审阅后应用，原稿不会被模型任务直接覆盖。大纲评论调用原始 `revise_outline`。

## 与 v2 表达资产的关系

`prototype/v2.mjs` 中的 7 种策略、L1/L2/L3、XYZ/CAR/PAR、项目背景及反八股正反例仍作为原始资产保存在仓库，但原 v2 流程采用独立 cards.json 与一卡一 bullet，和当前统一 Wiki 结构不兼容。本轮没有把该编译器直接接回主链；因此完整表达规范仍需下一次有针对性地迁入原有 `compose` 提示词或独立参考层，不能宣称已全部使用。

## 已知限制

原始链路的 `selection_guard` 会过滤未获评估支持的经历，大纲手动新增未入选的经历会被原有 validateOutline 拒绝。需明确设计重新评估或手动加入的规则。原链的大纲和成稿更长、调用次数更多；端到端真实模型测试结果另记。
